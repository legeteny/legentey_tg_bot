# legentey_tg_bot — тег-бот для Telegram

Бот на Java 21, который умеет упоминать всех известных ему участников группы командой `/all`,
а также превращать сообщения в стикеры-цитаты (`/q`) — рендер берёт самостоятельно развёрнутый
[quote-api](https://github.com/legeteny/quote-api) (форк движка, на котором работает @QuotLyBot;
оригинал — [LyoSU/quote-api](https://github.com/LyoSU/quote-api)).
Никаких сторонних Telegram-библиотек — прямые HTTP-запросы к Bot API (`java.net.http.HttpClient`) + Jackson для JSON.
Данные (участники чатов, стикерпаки) хранятся в SQLite-файле, чтобы бот переживал перезапуски.

## Как это работает и главное ограничение

Telegram Bot API **не даёт ботам получить полный список участников группы** (даже если бот — админ).
Поэтому, как и все подобные боты, этот работает так:

- бот запоминает пользователя, когда видит от него сообщение в группе, либо когда пользователь
  вступает в группу, пока бот в ней состоит;
- при выходе пользователя из группы бот забывает его;
- `/all` упоминает только тех, кого бот успел так «увидеть».

Из этого следует: **сразу после добавления бота список будет пустым/неполным**, он пополнится
по мере переписки в чате.

Чтобы бот видел *все* сообщения в группе (а не только адресованные ему команды), нужно одно из двух:

1. Отключить Privacy Mode у бота через [@BotFather](https://t.me/BotFather): `/setprivacy` → выбрать бота → `Disable`.
2. Либо сделать бота администратором группы — админам Telegram присылает все сообщения независимо от Privacy Mode.

Сделать и то, и другое не помешает.

## Команды

| Команда       | Описание |
|---------------|---|
| `/all`        | Упомянуть всех известных участников чата |
| `/q <эмодзи>` | Ответом на сообщение — превратить его в стикер-цитату и добавить в стикерпак этого чата |

`/q` вызывается реплаем на любое сообщение в любом чате — использовать может кто угодно:

1. Бот берёт настоящего автора и текст сообщения (плюс форматирование — жирный,
   курсив, кастомные эмодзи и т.п. передаются как есть) и отправляет их напрямую
   в `quote-api` — свой же контейнер, поднятый рядом в `docker-compose.yml`.
   Если реплай сделан на **пересланное** сообщение, автором ставится оригинальный
   отправитель (по `forward_origin`), а не тот, кто его переслал.
2. `quote-api` рендерит PNG-открытку с этой цитатой и возвращает её.
3. Бот загружает картинку в стикерпак **этого** чата (у каждого чата свой пак,
   создаётся при первом использовании — Bot API не даёт добавлять стикеры в чужие
   паки, даже созданные вручную тем же человеком) и присылает ссылку на пак прямо
   в чат, где вызвали `/q`.

Никакой пересылки между чатами и никакого стороннего бота — раньше был обходной путь
через @QuotLyBot (реплей в служебном чате), но он не мог правильно определить автора
чужого сообщения (Telegram-пересылки теряют это для ботов), поэтому от него отказались.

Вызвать может любой участник чата, но владельцем стикерпака в Telegram всегда
числится один и тот же человек — тот, чей user_id указан в `ADMIN_CHAT_ID`
(см. ниже), независимо от того, кто вызвал `/q`.

### Перерендер всех стикеров-цитат

Каждый созданный `/q`-стикер бот запоминает вместе с исходными данными рендера
(автор, текст, форматирование) и его `file_id` в стикерпаке. Ширина открытки
(`width`, передаётся в `quote-api`) хранится не константой в коде, а в SQLite —
её можно менять на лету и переприменять к уже созданным стикерам «на месте»,
без пересоздания паков и без потери позиций/эмодзи у существующих стикеров.

Вместе с этим бот замораживает на момент создания стикера три поля автора:
аватарку (как Telegram `file_id`, не сами байты — quote-api и наш бот работают
с одним `BOT_TOKEN`, так что file_id остаётся рабочим), premium-эмодзи-статус
и username. При перерендере используются именно эти замороженные значения —
даже если автор потом сменил аватарку или статус, старый стикер при
`/q_rerender` не «уедет» на новые. Если какое-то из полей не было сохранено
(например, у автора на момент создания не было аватарки/статуса, или стикер
создан до появления этой логики) — для него на лету подтягивается текущее
значение автора, и один раз успешно найденное значение сохраняется в базу,
чтобы больше не запрашивать его каждый раз. Стикеры, для которых в базе вообще
нет записи (совсем старые, из до-трекинговых времён) `/q_rerender` не трогает —
просто пропускает, ничего не ломает и не удаляет.

`replaceStickerInSet` по документации должен сохранять позицию стикера внутри
пака сам, но на практике это не подтвердилось — после первого `/q_rerender`
перерендеренные стикеры оказались в самом начале пака вместо своих прежних
позиций. Поэтому бот больше не полагается на это: перед заменой запоминает
текущую позицию каждого стикера в паке, а после `replaceStickerInSet`
принудительно возвращает его на то же место через `setStickerPositionInSet`.
Нетронутые (не отслеживаемые) стикеры при этом никак не двигаются — их позиции
просто не пересчитываются заново.

Три скрытые команды (не показываются в подсказках Telegram) — доступны только
человеку с `ADMIN_CHAT_ID`, писать их нужно боту в личку:

| Команда | Описание |
|---|---|
| `/q_get_width` | Показать текущую ширину рендера |
| `/q_set_width <число>` | Установить новую ширину — действует только на новые `/q`-стикеры |
| `/q_rerender` | Перерендерить все уже существующие стикеры-цитаты во всех чатах с текущей шириной и заменить их в стикерпаках через `replaceStickerInSet` |

Обычный сценарий смены ширины: `/q_set_width 200`, затем `/q_rerender` —
последняя команда проходит по всем сохранённым стикерам во всех паках и
отвечает числом обновлённых и не обновившихся.

## Настройка

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Отключите Privacy Mode (`/setprivacy` → `Disable`) — см. выше, зачем.
3. Скопируйте `.env.example` в `.env` и впишите токен:

   ```bash
   cp .env.example .env
   ```

   Переменные:
   - `BOT_TOKEN` — токен от BotFather (обязательно)
   - `POLL_TIMEOUT_SECONDS` — таймаут long polling в секундах (по умолчанию `30`)
   - `ADMIN_CHAT_ID` — если задан: бот при каждом запуске присылает в этот chat_id
     список всех коммитов, появившихся с прошлого такого сообщения (узнать свой id —
     @userinfobot). Если новых коммитов нет — например, контейнер просто перезапустили —
     приходит короткое сообщение с текущим коммитом.
     Также используется как владелец всех стикерпаков, создаваемых `/q` — без него
     `/q` не работает ни для кого
   - `QUOTE_API_URL` — необязательно; адрес сервиса quote-api (по умолчанию
     `http://quote-api:3000` — сервис из того же `docker-compose.yml`)

При деплое через `.github/workflows/deploy.yml` `GIT_COMMIT`/`GIT_COMMIT_MESSAGE`, а также
`GIT_RECENT_COMMITS` (последние 50 коммитов, base64 — многострочное значение не переживёт
разбор `.env`), берутся автоматически из git на сервере (раннер уже сделал checkout),
а `ADMIN_CHAT_ID` — из одноимённого секрета репозитория на GitHub. При локальном запуске
эти переменные не нужны — бот сам спросит `git` в рабочей папке.

Границу «что уже анонсировано» бот держит у себя в SQLite и записывает только после того,
как Telegram принял сообщение. Поэтому упавший деплой или недоступный Telegram не съедают
коммиты — они попадут в следующий анонс. В образе бота нет ни `git`, ни репозитория, так что
история приходит только через переменные окружения.

## Запуск в Docker (рекомендуется)

```bash
docker compose up -d --build
```

Поднимает два контейнера: сам бот и `quote-api` (сборка второго идёт из его GitHub-репозитория
и занимает заметно больше времени/места — там тяжёлые нативные зависимости для рендеринга).

Данные (SQLite-файл) сохраняются в `./data` на хосте — том примонтирован в `/data` внутри контейнера,
переживает пересборку и перезапуск контейнера.

Логи:

```bash
docker compose logs -f
```

Остановить:

```bash
docker compose down
```

## Локальный запуск без Docker

Нужны JDK 21 и Maven.

```bash
mvn -q package
BOT_TOKEN=xxx:yyy java -jar target/tgbot.jar
```

`/all` заработает сразу. Для `/q` нужен ещё и запущенный `quote-api`, доступный по
`QUOTE_API_URL` — без Docker его придётся поднимать отдельно (см. его README).

```
│   ├── ChatUser.java

│   ├── QuoteSticker.java
│   ├── RenderSettingsStore.java — интерфейс хранилища ширины рендера (/q_get_width, /q_set_width)

│   ├── DeployStore.java        — интерфейс хранилища "последний анонсированный коммит"

    ├── BotService.java         — цикл long polling, разбор апдейтов
    ├── CommandHandler.java     — обработка команд

    ├── MentionFormatter.java   — сборка сообщений с упоминаниями (MarkdownV2),
    │                              разбивка на части по лимиту в 4096 символов
    └── StickerService.java     — рендер цитаты через quote-api и управление стикерпаками
```
